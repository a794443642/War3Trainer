War3Trainer 使用与开发手册
========================================
适用版本：V16（2026-10-27）
项目地址：https://github.com/a794443642/War3Trainer


一、这是什么
----------------------------------------
War3Trainer 是《魔兽争霸 III：冰封王座》的内存修改器。它读取游戏进程内存，
按版本定位英雄属性、金钱木材、单位数据等地址，并把新值写回去。

除了经典的属性修改，现在还有：
  · 内存搜索：不知道地址时，用数值扫描把地址找出来
  · 指针链扫描：把「模块 + 偏移 + 多级指针」存下来，重启游戏后仍然可用
  · 按键定位：用热键触发一次，记录当时的堆地址
  · 地址收藏：把常用地址存成清单
  · 定时重写：按固定间隔反复写回，压住地图脚本的每帧重算

仅限单机 / 自建局域网地图，不适用于任何对战平台。


二、运行环境与安装
----------------------------------------
· Windows，已安装 .NET Framework 4.8
· 需要管理员权限：读写其他进程的内存要用 SeDebugPrivilege，
  程序清单声明了 requireAdministrator，启动时会弹 UAC
· 32 位魔兽争霸 III（1.20e ~ 1.28f），兼容网易对战平台的 dzwar3 进程

安装：解压后直接运行 War3Trainer.exe，不需要写入注册表。
数据只写在自己的目录里（见第六节）。


三、快速上手
----------------------------------------
1. 启动魔兽，进入一张单机地图（自定义游戏 / 战役）
2. 运行 War3Trainer.exe，UAC 提示点「是」
3. 点工具栏「查找游戏」。状态栏显示「游戏已运行(PID)，版本：x.x.x.xxxxx（支持）」
   即连接成功；版本不支持时会提示具体版本号
4. 在「功能修改」页左侧选分类（游戏资源 / 选中单位 / 物品列表 / 英雄属性），
   右侧表格会列出地址和当前值
5. 双击「修改」列填新值，按 F6 写入

想让修改不被地图脚本改回去：保持工具栏「定时重写」勾选，间隔默认 500 ms。


四、界面说明
----------------------------------------
4.1 工具栏（三个页签通用）
    查找游戏     重新扫描 war3 / dzwar3 进程
    刷新(F5)     重新读取当前分类的数值
    修改(F6)     把「修改」列的值写进内存
    定时重写     总开关（默认开）
    间隔         重写间隔，可手填 100 ms / 0.5s / 1 秒，范围 50ms~60 秒
    状态提示     游戏未运行 / 已运行(PID, 版本) / 版本不支持 / 请以管理员身份运行

4.2 功能修改
    左：功能树（游戏资源、选中单位、物品列表、英雄属性……）
    右：表格，列为 名称 / 数值 / 修改 / 定时重写
    · 双击「修改」列（或选中行直接输入）填值，Enter 提交并跳到下一行，Esc 取消
    · 未写入的修改在切换分类时会自动提交
    · 「其他 → 数值倍数修改」把当前值按 2x~5x 预填，省得手算
    · 「其他 → 加大修改长度」输入上限 7 位 → 35 位（大数值 / Char4）
    · 「定时重写」列显示该行当前被压住的值

4.3 内存搜索
    · 数值类型：Int32 / Float / Char4 / UInt16
    · 首次扫描：填「数值」后按类型搜索；数值留空 = 未知初始值搜索
    · 再次扫描：等于数值 / 变化了 / 未变化 / 增大了 / 减小了
    · 倍数：界面值 = 内存值 / 倍数，例如生命值显示 113.0 时内存里可能是 1130000
    · 容差：按内存原始值算；填了倍数要一起乘（倍数 10000、容差 500 表示 ±0.05）
    · 只搜索 game.dll（推荐）：只扫 Game.dll 静态区，快且误报少；搜不到就取消勾选
    · 自动刷新数值：每秒刷新结果列表
    · 结果列表：地址 / 当前值 / 类型，支持多选、Ctrl+C 复制、右键菜单
    · 底部：写入选中地址的值 · 写入 · 添加到收藏… · 扫描指针链… · 按键定位… · 导出内存…
    · 双击结果行 = 直接加入收藏

4.4 地址收藏
    表格列：名称 / 地址表达式 / 当前地址 / 当前值 / 类型 / 定时重写 / 备注
    按钮：新增(N) 编辑(E) 删除(D) 写入(W) 保存(S) 重新载入(R)
          指针链(P) 重新定位(A) 清理失效(X)
    · 地址表达式形如 game.dll+AD5C18，或 game.dll+AD5C18>0x10>0x20 的多级指针链
    · 按键定位条目存的是堆地址，重启游戏后点「重新定位」恢复
    · 清理失效：进图后一次性删掉解析不出数值的条目（会跳过按键定位条目）
    · 收藏文件默认在 %APPDATA%\War3Trainer\addresses.xml，保存时自动留 .bak

4.5 定时重写
    地图脚本每帧重算数值，只写一次会被改回去。定时重写按间隔反复写：
    · 功能修改页：开关打开时，F6 写入过的行自动登记
    · 地址收藏页：条目勾上「定时重写」就按同一间隔回写
    · 开关和间隔存在 rewrite.txt（与 addresses.xml 同目录），下次启动继续生效
    · 关掉总开关 = 完全停止回写，只写一次的行为不变

4.6 菜单
    文件(F)：调试专用-ReadFromGameMemory、退出(X)
    其他(W)：窗口总在最前、加大修改长度、数值倍数修改（1x~5x）
    工具(T)：内存搜索(S)、地址收藏(B)、导出内存(D)…、打开收藏文件位置(O)
    帮助(H)：关于修改器(A)


五、命令行参数
----------------------------------------
War3Trainer.exe [--tab=0|1|2] [--book=<收藏文件路径>]

  --tab=0   启动时打开「功能修改」（默认）
  --tab=1   启动时打开「内存搜索」
  --tab=2   启动时打开「地址收藏」
  --book=   指定收藏文件，便携模式用（把 addresses.xml 放在程序旁边）

示例：War3Trainer.exe --tab=1 --book=.\portable\addresses.xml


六、数据文件
----------------------------------------
  addresses.xml   %APPDATA%\War3Trainer\   地址收藏（自动留 .bak）
  rewrite.txt     与收藏文件同目录          定时重写的开关与间隔
  crash.log       %APPDATA%\War3Trainer\   未处理异常日志
  收藏目录无法写入时，会退回到程序所在目录。
  用 --book= 时，rewrite.txt 也跟着收藏文件走。


七、常见问题
----------------------------------------
Q: 工具栏显示「请以管理员身份运行」
A: 没拿到 SeDebugPrivilege。关闭后右键「以管理员身份运行」。

Q: 显示「游戏已运行，但版本（x）不被支持」
A: 只支持 1.20e ~ 1.28f。请确认游戏版本，或换对应版本。

Q: 找到了地址，重启游戏后就失效
A: 用「地址收藏」存成模块+偏移或指针链；堆地址（按键定位）重启后点「重新定位」。

Q: 搜不到数值
A: ① 数值被显示取整了 —— 填容差 0.05；② 数值不在 game.dll —— 取消「只搜索 game.dll」；
   ③ 先留空做未知初始值扫描，再反复用「变化了 / 增大了」筛选。

Q: 修改几秒后自己变回去
A: 地图脚本在重算。打开「定时重写」，把间隔调小（如 100 ms）。

Q: 联机会掉线
A: 局域网联机要求每台机器做完全相同的修改，否则数据不同步。本工具不向网络发送数据。


八、限制与注意事项
----------------------------------------
1. 仅限单机：自定义游戏 / 战役。
2. 不适用于对战：官方战网、任何对战平台都不行。
3. 局域网：每台机器都要做同样的修改，否则立刻掉线。
4. 定时重写只影响本机游戏进程内存，不改游戏文件。


九、源码结构
----------------------------------------
  Program.cs              入口 / 命令行 / 崩溃日志
  MainForm.cs             主窗体：功能树、属性表、写入

  GameTrainer.cs          内置地址表（属性 / 资源 / 单位 / 物品）

  War3Common.cs           游戏内存结构解析
  MemoryScanner.cs        数值扫描（首次 / 再次 / 未知值）
  PointerScanner.cs       指针扫描
  PointerScannerChains.cs 多级指针链
  KeyLocator.cs           按键定位
  AddressBook.cs          地址收藏（XML 存取 / 解析 / 重新定位）
  RewriteEngine.cs        定时重写引擎 / 间隔解析 / 配置
  *Dialog.cs              各对话框（指针链、按键定位、内存导出、收藏编辑）


十、附：内存结构笔记（原 2011 版手册，以 1.22.0.6328 为例）
----------------------------------------
以下内容来自原作者 tctianchi 的逆向笔记，数字均为十六进制。
它是 GameTrainer.cs 里内置地址表的依据；新版游戏地址不同，
但结构关系基本一致，做二次开发时仍有参考价值。

【1】从选中单位的列表获得单位 ESI
  1. [6FAA2FFC]，参考 sub_6F416AE0
  2. [上面+58+4*a2]，参考 6f3a0564；其中 a2 = word ptr[上面+28]，参考 6F042B76
  3. [上面+34] 记为链表基地址，参考 6f2cc0a8
  4. 链表基地址结构：[+1F0] 表头、[+1F4] 表尾、[+1F8] 表长度（参考 sub_6F415B70）
  5. 展开节点：[节点+0] 下一个节点、[节点+4] not 下一个节点、[节点+8] 单位 ESI
     （参考 6F412504、6f412518）

【2】重要说明
  1. ESI 记为 ThisUnit；[ThisUnit+1E4] 记 UnitAttributes；[ThisUnit+1EC] 记 HeroAttributes
  2. 算法 0（6F03F180）：从 GameMemory 取数，需要 Index1 和 ReferenceNumber1
     (1) [6FAA4178] 记 ThisGame
     (2) [ThisGame+0xC] 记 ThisGameMemory
     (3) [ThisGameMemory + Index1*8 + 4] 记 Address1，并返回
     (4) [Address1+0x18] 应等于 ReferenceNumber1
  3. 算法 1（6F4634E0）：先用算法 0，再 Address1 + 0x78 作为输出地址
  4. 算法 2（6F468A20）：[ThisGameMemory + Index1*8 + 4] 记 Address3；
     [Address3+20] 为 0 时返回 [Address3+54]

【3】单位的修改
  1. HP float：[HPMax 地址 - C]
  2. HPMax float：ThisUnit+98 → [+8] → 算法 0 → [结果+84]（参考 6F46752F）
  3. MP float：[MPMax 地址 - C]
  4. MPMax float：ThisUnit+98 → [+28] → 算法 0 → [结果+84]（参考 6F467750）
  5. 经验值：[HeroAttributes+8C] int（6F26DFF0，getHeroExp）
  6. 力量初值：[HeroAttributes+94] int（6F353D06）
  7. 敏捷初值：[HeroAttributes+A8] int
  8. 智力初值：[HeroAttributes+7C+2*4] 为 Index1，[+7C+3*4] 为 ReferenceNumber1，
     用算法 1 得到地址（6F0DA9D0）
  9. 攻击频率：[UnitAttributes+1B0] float（6F0C64E0，比值，两种武器通用）
 10. 武器射程：[UnitAttributes+258+index*8]，index 取 0 / 1（6F352CA3、6F0C61A5）
 11. 攻击相关偏移（int）：
       攻击1 - 基础1 A0、基础2 AC、倍乘 94、骰子 88、种类 F4
       攻击2 - 基础1 A4、基础2 B0、倍乘 98、骰子 8C、种类 F8
 12. 移动速度：[参数+70] float 或 [参数+78] float 比值（6F201190）
     “参数”的获取：从 6F077693 开始，[ThisUnit+1D8] 记 MoveAbilityIndex，
     算法 2 得到 I；若 [I+24] & [I+28] != -1，检查 [[I]+2D4] 是否等于 6F201190，
     是则用 [I+70]/[I+78]，否则 I = 算法 2([I+24]) 继续
 13. 防御：[ThisUnit+E0] float（6F353250）
 14. 防御类型：[ThisUnit+E4] int
 15. 坐标 X：ThisUnit+164 → [+8]/[+C] 走算法 0 → [+78] → [0]（6F2776C4 等）
 16. 坐标 Y：[坐标X 的地址 + 4]

【4】金钱（6F407220）
  1. [ThisGameMemory + 1*8 + 4] 记 Address2，取高 16 位
  2. 低 16 位是玩家基址：
       1P 0190  2P 1410  3P 26A0  4P 3920  5P 4BB0  6P 5E30
       7P 70C0  8P 8350  9P 95D0 10P A860 11P BAE0 12P CD70
  3. 每个玩家：金钱 +0（int ×10）、木头 +80（int ×10）、
     最大人口 +180（int）、当前人口 +200（int）

【5】物品列表（sub_6F26E0E0）
  1. [SelectedUnit+1F4] 记 List；为 0 直接返回
  2. List + C*ItemIndex + 0x70 记 Index1（不解引用），ItemIndex = 0~5
  3. 算法 0（Index1，[Index1+4]）得到 RawItem
  4. RawItem 为 0 或 [RawItem+0x20] 非 0 时返回 0
  5. [RawItem+0x54] 是物品基地址 CurrentItem

【6】物品修改
  1. 使用次数 [CurrentItem+84]
  2. 名称 [CurrentItem+30]
